# 5. WorkerServiceServer

Generated code

```go
type WorkerServiceServer interface {

    RegisterWorker(...)

    SubmitJob(...)

    Heartbeat(...)

}
```

Notice

it's an interface.

Why?

Because gRPC doesn't know

how

you want to implement

those functions.

It only knows

they must exist.

---

Think of it like this.

Google says

> "If you promise to implement these methods,
> I'll handle all the networking."

That's exactly what the interface represents.

# 17. Why Are Request and Response Objects Separate?

Notice

```

SubmitJobResponse
```

instead of


Why?

Because

should not expose

internal data structures.

Maybe later

```

Internal Flags

Mutex

Logger

Cache
```

None of those belong

on the network.

Network models

and

serve different purposes.

# 19. Engineering Decision (ADR-008)

## Context

Quorum needs reliable communication between distributed workers.

## Decision

Rely on generated gRPC code instead of manually implementing networking.

## Why?

- Reduces bugs.
- Consistent protocol handling.
- Easier maintenance.
- Automatic compatibility with future gRPC improvements.

## Consequences

Positive

- Minimal networking code.
- Strong contracts.
- Easier testing.

Negative

- Developers must understand generated code rather than writing it themselves.

# 21. Connection to Quorum

Every generated type now has a clear purpose:

```
worker.proto
        │
        ▼
protoc
        │
 ┌──────┴───────────┐
 │                  │
 ▼                  ▼
worker.pb.go    worker_grpc.pb.go
 │                  │
 ▼                  ▼
Messages       RPC Infrastructure
                    │
                    ▼
          WorkerServiceServer (interface)
                    │
                    ▼
             WorkerServer (our implementation)
                    │
                    ▼
             WorkerManager
                    │
                    ▼
                 Workers
```

Notice something important:

**Everything above `WorkerServer` is generated.**

**Everything below `WorkerServer` is our code.**

That separation is intentional.

Google owns the networking infrastructure.

We own the business logic.

---

# Key Takeaways

- `WorkerServiceServer` is a generated interface describing the server contract.
- `WorkerServer` is our implementation of that contract.
- `WorkerServiceClient` is the client-side abstraction used to invoke remote methods.
- `UnimplementedWorkerServiceServer` provides forward compatibility when services evolve.
- Generated code hides serialization, HTTP/2, TCP, and routing, allowing Quorum to focus on scheduling logic rather than networking.
